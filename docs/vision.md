# Vision: API-витрина МойСклад

## Идея

Сервис — это REST-обёртка над JSON API МойСклад (Remap 1.2), которая повторяет
покупательский сценарий витрины «Онлайн-заказ»: показать каталог так, как он настроен
в МойСклад, проверить наличие и оформить заказ. Собственных данных сервис не хранит —
источник истины МойСклад.

## Полный пользовательский сценарий (end-to-end)

1. **Каталог** — клиент получает товары витрины с ценами и остатками:
   `GET /api/products` (с настройками отображения, пагинацией и фильтрами).
2. **Проверка доступности** — клиент передаёт выбранные позиции и количество:
   `POST /api/availability`; сервис отвечает, хватает ли остатков.
3. **Создание заказа** — если позиции доступны, сервис создаёт заказ покупателя
   в МойСклад: `POST /api/orders`.
4. **Чтение заказа** — клиент проверяет результат по идентификатору:
   `GET /api/orders/{id}` (состав, количество, суммы, статус).

Это целевой сценарий проекта целиком: от просмотра витрины до подтверждённого заказа
в учебном аккаунте МойСклад.

## Границы по этапам

- **Sprint 5 (текущий):** витрина и её настройки — каталог, options/config,
  пагинация, фильтрация, витринная логика «Онлайн-заказ».
- **Sprint 6 и далее:** создание и чтение заказов. Это **ядро итогового MVP**,
  а не «необязательная» функциональность; на текущей неделе мы сознательно
  откладываем заказы, чтобы сначала стабилизировать витрину.
- **После заказов:** MCP-интерфейс — те же возможности (каталог, остатки,
  доступность, заказы) в виде инструментов для AI-агентов.

## Функциональный объём проекта

| Блок | Возможности | Этап |
|---|---|---|
| Каталог | список товаров, цены, остатки | Sprint 5 |
| Настройки витрины | тип цен, группы товаров, показ остатков, набор полей | Sprint 5 |
| Навигация | пагинация, фильтрация | Sprint 5 |
| Доступность | проверка позиций по остаткам | Sprint 5 (готово) |
| Заказы | создание заказа, чтение заказа по id | Sprint 6 |
| MCP | инструменты каталога, остатков, доступности, заказов | после Sprint 6 |
| Эксплуатация | health, метрики, логи с correlation ID, Swagger | Sprint 5 (готово) |

## Принципы

- **Тонкие контроллеры**: валидация входа и делегирование в сервисы.
- **Функциональный Java 21**: records, Streams, `Optional`, method references.
- **Деньги — только `BigDecimal`**: разбор из строки, сравнение через `compareTo`,
  арифметика через `add`/`multiply`/`divide` с `RoundingMode`.
- **Понятные ошибки**: структурированный `ErrorResponse`, корректные HTTP-статусы,
  без стектрейсов наружу.
- **Разделение DTO**: Remap-модели (`...RemapDto`) не выходят за слой клиента/маппера.
- **Никаких секретов в репозитории**: токен только из окружения / `.env`.

## Out of Scope (для проекта в целом)

- Собственная БД сервиса (источник данных — только МойСклад).
- Корзина и платёжный сценарий на стороне сервиса.
- Авторизация покупателей и персональные цены контрагентов.
- Административный интерфейс и произвольная запись данных в МойСклад.

## Критерий успеха проекта

Полный end-to-end сценарий на `curl` и Swagger UI:
настроить витрину → получить постраничный отфильтрованный каталог → проверить
доступность → создать заказ → прочитать созданный заказ. Плюс те же операции
через MCP-инструменты. Всё — на реальных данных учебного МойСклад.
