# Product Backlog

Формат элемента: **что сделать · зачем · готово, если**

Своей БД и корзины в сервисе нет — позиции для проверки и заказа передаются в запросе.

## P0 — критично для спринта 2

### Токен Remap и безопасное хранение
- **Что:** токен JSON API из окружения (env / local properties)
- **Зачем:** доступ к API без утечки секрета
- **Готово, если:** сервис читает токен из env; токена нет в репозитории

### Публичная витрина: каталог из нового assortment
- **Что:** Spring-клиент к `/entity/assortment` (Remap 1.2)
- **Зачем:** полка магазина
- **Готово, если:** REST отдаёт список позиций витрины

### `GET /api/products` — id, имя, артикул, цены
- **Что:** REST-эндпоинт для каталога
- **Зачем:** клиент видит товары
- **Готово, если:** `curl /api/products` возвращает товары

## P1 — следующий спринт

### Остатки на витрине
- **Что:** отчёт stock + склейка с ассортиментом
- **Зачем:** видно наличие
- **Готово, если:** в списке/карточке есть остаток

### Витрина для контрагента (упрощённо)
- **Что:** персональный каталог / тип цен
- **Зачем:** персональный каталог
- **Готово, если:** задокументированный режим и демо

### Проверка доступности
- **Что:** остатки по позициям из тела запроса
- **Зачем:** не оформляем заказ без наличия
- **Готово, если:** при нехватке — понятный отказ, заказ не создан

### Создать заказ покупателя
- **Что:** создание заказа из позиций запроса после проверки
- **Зачем:** покупка
- **Готово, если:** заказ есть в учебном МойСклад

### Прочитать заказ
- **Что:** чтение заказа по id
- **Зачем:** проверить результат
- **Готово, если:** REST отдаёт состав и статус
