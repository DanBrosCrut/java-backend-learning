# Product Backlog

Формат элемента: **что сделать · зачем · готово, если**

Своей БД и корзины в сервисе нет — позиции для проверки и заказа передаются в запросе.
Полный целевой сценарий проекта: каталог → проверка доступности → создание заказа →
чтение заказа, затем MCP-интерфейс (см. `docs/vision.md`).

## P0 — Sprint 5: витрина и её настройки

### Настройка витрины (options/config)
- **Что:** параметры каталога, повторяющие настройки витрины «Онлайн-заказ»:
  тип цен, группы товаров, показ остатков, набор полей
- **Зачем:** клиент видит каталог так, как он настроен в МойСклад
- **Готово, если:** `GET /api/products` принимает опции и/или `GET /api/products/config`
  отдаёт доступные значения; результат меняется согласно выбранной конфигурации

### Пагинация каталога
- **Что:** `GET /api/products?page=0&size=20` с обёрткой ответа
- **Зачем:** каталог может быть большим, клиенту нужны порции
- **Готово, если:** ответ содержит `items`, `total`, `page`, `size`;
  неверные `page`/`size` дают 400

### Фильтрация каталога
- **Что:** фильтры в рамках разрешённых настроек: по названию/артикулу,
  по группе товаров, «только в наличии»
- **Зачем:** покупателю нужен поиск по витрине
- **Готово, если:** фильтры комбинируются с пагинацией, описаны в Swagger,
  неизвестный параметр не ломает запрос

### Витринная логика «Онлайн-заказ»
- **Что:** скрытие товаров без остатка (если включено), выбор типа цен для вывода,
  ограничение видимыми группами
- **Зачем:** поведение API совпадает с настройками витрины МойСклад
- **Готово, если:** на демо-данных видно, что настройка меняет состав и цены каталога

## P1 — Sprint 5/6: стабилизация и демо

### Документация MVP-витрины
- **Что:** README и Swagger: запуск, env, примеры curl для каталога,
  доступности и настроек витрины
- **Зачем:** MVP должен быть воспроизводим и понятен проверяющему
- **Готово, если:** по README можно поднять сервис и пройти демо-сценарий

### Расширить Remap-модель каталога
- **Что:** добавить в `RemapAssortmentRow` группу товара (`productFolder`),
  при необходимости — единицы измерения и изображения
- **Зачем:** без группы невозможны фильтрация и настройка «видимые группы»
- **Готово, если:** маппер получает группу, каталог её отдаёт или использует для фильтра

## P1 — Sprint 6: заказы (ядро итогового MVP)

### Создать заказ покупателя
- **Что:** `POST /api/orders`: создание заказа из позиций запроса после проверки остатков
- **Зачем:** завершение сценария покупки
- **Готово, если:** заказ создан в учебном МойСклад; при нехватке остатка — отказ
  без создания заказа (502/409 по ситуации, структурированный `ErrorResponse`)

### Прочитать заказ
- **Что:** `GET /api/orders/{id}`: состав, количества, суммы, статус
- **Зачем:** проверить результат оформления
- **Готово, если:** REST отдаёт заказ из МойСклад; неизвестный id → 404

## P2 — после Sprint 6: MCP и эксплуатация

### MCP: каталог и остатки
- **Что:** инструменты MCP для списка товаров и остатков
- **Зачем:** витрина доступна AI-агентам
- **Готово, если:** инструменты возвращают те же данные, что REST

### MCP: доступность и заказы
- **Что:** инструменты проверки доступности, создания и чтения заказа
- **Зачем:** полный сценарий покупки через агента
- **Готово, если:** сценарий воспроизводится через MCP на учебном аккаунте

### Кэширование каталога и остатков
- **Что:** кэш с TTL для assortment и stock report
- **Зачем:** снизить нагрузку и время ответа
- **Готово, если:** повторные запросы не бьют в Remap чаще TTL

### CI, Docker, версионирование
- **Что:** GitHub Actions, Dockerfile/docker-compose, API-версия `/v1`
- **Зачем:** воспроизводимая сборка и запуск
- **Готово, если:** пайплайн зелёный, контейнер поднимается, версия в пути

### Контрактные тесты Remap
- **Что:** тесты на структуру ответов Remap 1.2
- **Зачем:** ловить изменения внешнего API
- **Готово, если:** контрактные тесты падают при изменении схемы Remap

## Done — реализовано ранее

- Токен Remap из окружения (без секретов в репозитории)
- `GET /api/products` — каталог из `assortment` (id, имя, артикул, цена)
- Остатки на витрине: отчёт `stock` + склейка с ассортиментом
- `POST /api/availability` — проверка доступности позиций
- `GET /health`, Actuator, Swagger UI, correlation ID в логах
- Глобальный обработчик ошибок и структурированный `ErrorResponse`
- Конфигурация через YAML-профили (`dev`, `prod`)
- Java 21 refactor: records, Streams, Optional, BigDecimal

- Административный интерфейс и произвольная запись данных в МойСклад
