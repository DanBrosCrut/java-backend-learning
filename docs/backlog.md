# Product Backlog

Формат элемента: **что сделать · зачем · готово, если**

Собственной БД нет: товары, цены и остатки приходят из МойСклад. Корзина — файловый MVP
(`data/cart.json`, Sprint 7), а не отдельная БД. Полный целевой сценарий проекта:
каталог → корзина → проверка перед заказом → создание заказа → чтение заказа, затем
MCP-интерфейс (см. `docs/vision.md`).

## P0 — Sprint 5: витрина и её настройки (Done)

- [x] **Настройка витрины (options/config).** `priceType`, `groups`, `fields`,
  `inStockOnly`; `GET /api/products/config` отдаёт доступные значения.
  Готово: каталог меняется согласно настройкам, неизвестные опции →
  `400 INVALID_CATALOG_OPTION`.
- [x] **Пагинация каталога.** `page`/`size`, ответ `{items,total,page,size}`.
  Готово: неверные `page`/`size` → `400 INVALID_PAGINATION`, `total` считается
  после фильтров.
- [x] **Фильтрация каталога.** `q` по названию и артикулу, `groups`, `inStockOnly`.
  Готово: фильтры комбинируются с пагинацией и описаны в Swagger.
- [x] **Витринная логика «Онлайн-заказ».** Скрытие нулевых остатков, выбор типа цен,
  ограничение видимыми группами. Готово: настройка меняет состав и цены каталога.

## P0 — Sprint 6: полный каталог, кеши и остатки (Done)

- [x] **Полный ассортимент постранично.** Remap отдаёт не больше 1000 строк, клиент

- [x] **Кеш ассортимента.** Снапшот в памяти, `X-Cache: HIT/MISS`, инвалидация
  `?invalidate=true` (PR #90).
- [x] **Текущие остатки.** `/report/stock/all/current?stockType=stock`, слияние
  с каталогом по `assortmentId` (PR #91).
- [x] **Группа товара в Remap-модели.** `pathName` используется для фильтра по группам.
- [x] **Документация и сквозные тесты.** README, Swagger, `CatalogFlowTest` (PR #92).

## P0 — Sprint 7: delta-кеш и пользовательский сценарий (в ревью)

- [x] **Delta-синхронизация остатков.** TTL 5 минут; при возрасте данных до 24 часов —
  `changedSince` + `include=zeroLines` и merge; раз в 24 часа — полный отчёт.
  `?invalidate=true` / `X-Force-Refresh: true` форсируют полное обновление (PR #94).
- [x] **Файловая корзина MVP.** `data/cart.json`, `POST /api/cart/items`,
  `GET /api/cart`, `DELETE /api/cart/items/{id}`, атомарная запись; корзина переживает
  перезапуск приложения (PR #96).
- [x] **Pre-order validation.** `POST /api/orders/validate` через `AvailabilityService`:
  `valid`, структурированные ошибки с `requested`/`available` и до трёх альтернатив;
  реальный заказ не создаётся (PR #96).
- [x] **Vision и backlog.** MCP переведён на P1, Sprint 6 отмечен выполненным,
  корзина описана как файловый MVP (Task 3).

## P1 — Sprint 8: заказы

### Создать заказ покупателя
- **Что:** `POST /api/orders`: создание заказа из позиций запроса после проверки остатков.
- **Зачем:** завершение сценария покупки.
- **Готово, если:** заказ создан в учебном МойСклад; при нехватке остатка — отказ
  без создания заказа и структурированный `ErrorResponse`.

### Прочитать заказ
- **Что:** `GET /api/orders/{id}`: состав, количества, суммы, статус.
- **Зачем:** проверить результат оформления.
- **Готово, если:** REST отдаёт заказ из МойСклад; неизвестный id → `404`.

## P1 — MCP-интерфейс

### MCP: каталог и остатки
- **Что:** `catalog_list`, `catalog_config`, `availability_check`.
- **Зачем:** витрина и остатки доступны AI-агентам.
- **Готово, если:** инструменты возвращают те же данные, что REST, и используют
  те же кеши.

### MCP: корзина и проверка заказа
- **Что:** `cart_get`, `cart_add_item`, `cart_remove_item`, `order_validate`.
- **Зачем:** агент собирает корзину и проверяет заказ до оформления.
- **Готово, если:** файловая корзина и структурированные ошибки совпадают с REST.

### MCP: заказы
- **Что:** `order_create`, `order_get` после реализации реальных заказов.
- **Зачем:** полный сценарий покупки через агента.
- **Готово, если:** сценарий воспроизводится через MCP на учебном аккаунте.

### MCP: единый контракт
- **Что:** общие DTO и коды ошибок для REST и MCP, описание побочных эффектов,
  запрет на токены в ответах инструментов.
- **Зачем:** предсказуемое поведение и безопасность.
- **Готово, если:** контрактные тесты MCP и REST проходят на одних и тех же запросах.
